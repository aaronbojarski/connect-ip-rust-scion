# Authentication
connect-ip-rust-scion uses x509 certificates for authenticating clients and proxies. The certificates are used during the QUIC handshake to establish a secure connection between the client and proxy. Both the client and proxy need to have their own certificate and private key. Furthermore, both sides need to trust the certificate authority (CA) that issued the other's certificate. This is done by providing the CA's certificate to the client and proxy. (Usually this is the same CA for both sides.)

## Generating Certificates
The testnet folder contains a script to generate a CA certificate, a proxy certificate, and a client certificate for testing purposes. The script uses OpenSSL to generate the certificates.

## Identifying Clients
Clients are identified by the Common Name (CN) field in their x509 certificate. The proxy can be configured to assign specific IP addresses to clients based on their CN, allowing for consistent addressing across reconnections. The mapping of CN to IP address can be provided to the proxy via its configuration file. Clients with a CN starting with "CIRS" (Connect-IP Rust SCION) followed by a unique identifier (e.g., "CIRS-Client1") are treated as managed clients. These clients can either have a specific IP address assigned in the configuration file, which they will always receive when connecting, or they will be allocated an address from the configured address pool if no specific assignment exists. Importantly, CIRS clients have proper connection teardown implemented, ensuring that routes and IPs announced by the client are properly removed from the proxy when the client reconnects before the previous connection's idle timeout has expired.

Clients without "CIRS" CNs are treated as ephemeral clients and are allocated an address from the address pool on each connection. These clients do not have proper connection teardown implemented, meaning that when such a client reconnects, the previous connection might still be considered active if its idle timeout has not yet expired, leading to potential address conflicts or stale routes. Therefore, it is recommended to use "CIRS" CNs for clients that require stable addressing and proper connection management.
