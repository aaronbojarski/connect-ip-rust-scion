# RFC 9484
RFC 9484 specifies the Connect-IP protocol, which is designed to tunnel IP packets over HTTP connections. Whenever possible, connect-ip-rust-scion follows the RFC closely. However, due to the specific characteristics of the SCION network architecture some deviations and adaptations were necessary. This document outlines these differences and the rationale behind them.

## MTU Considerations
We allow the user to specify the MTU for the tun interfaces. Based on this MTU, we decide whether to use QUIC datagrams or QUIC streams for tunneling IP packets. If the specified MTU is larger than 1150 bytes, we use QUIC streams to avoid fragmentation issues and enable IPv6 support. If the MTU is 1150 bytes or smaller, we use QUIC datagrams and drop IPv6 support, as tunneling IPv6 packets over QUIC datagrams would not be feasible due to MTU limitations. More details on the MTU calculations and considerations can be found in the [MTU Documentation](mtu.md).

## URI Template
We did not implement the `ipproto` and `target` parameters in the URI template as specified in the RFC. We do not require this functionality in our deployment scenarios, and omitting it simplifies the implementation.

## Link Local Traffic
We never tunnel link-local traffic, as this traffic is not routable and should remain within the local network segment. In case this is an issue for the local address that the proxy assigns to the client, this should be considered again.
